# CodeQL setup and validation — 2026-11-09

## Problem and verified baseline

The repository had no CodeQL workflow. GitHub's setup API returned `not-configured`, and
the analyses API returned `404: no analysis found` before this change. This was a missing
security-analysis configuration, not evidence that a prior scan found no vulnerabilities.

## Analysis contract

- Languages: Python and GitHub Actions, in separate matrix jobs.
- Query suite: `security-extended`; no source exclusions, skipped queries or suppressed alerts.
- Build mode: `none`, appropriate for the selected interpreted languages. No project installation,
  build or application execution runs in the upload-authorized job.
- Events: main pushes, pull requests targeting main, weekly scheduled checks and manual requests.
  No `pull_request_target`, event-dependent skip or continue-on-error path.
- Authority: read-only workflow default; only analysis jobs have `security-events: write`.
  Checkout does not persist credentials. Each job has a 20-minute deadline.
- Actions: reviewed full commit pins, including official CodeQL v4.39.3 commit
  `33d7b85da1a04171e211befe2c739303b9a4c066`.
- Storage: extractor/dependency caches and database uploads disabled. SARIF processing is awaited
  in GitHub's Code scanning service; the workflow adds no Actions artifact upload.

Structural YAML policy tests validate the actual workflow and independently reject twenty altered
configurations: privileged triggers, missing languages/schedules/deadlines, write-token expansion,
silent skips, ignored failures, mutable action refs, reduced queries, source filters, cache/database
uploads, disabled or unprocessed SARIF, and executable project steps.

## Local and hosted evidence

Local Windows/Python 3.14.6 verification passed 59 tests with 95.65% combined statement/branch
coverage against the unchanged 90% gate. Ruff format/lint, strict mypy (12 application modules),
isolated wheel/source-distribution builds and the installed-dependency audit passed. The unpublished
local project itself is not in the PyPI advisory database; the audit explicitly reported that skip.
CI still tests Python 3.11, 3.12 and 3.13 independently. An unrelated existing local pytest-cache
path was preserved; this run used a separate test-owned cache directory.

The pre-existing action-pin policy incorrectly accepted only owner/repository references and
rejected valid pinned subactions such as CodeQL's init/analyze. Its grammar now accepts nested
action paths while still requiring the complete forty-character commit. Positive ordinary/nested
references and negative mutable, overlong and malformed references are exercised independently.
No runtime vulnerability fix or zero-alert outcome is inferred from that policy correction.

The existing local validation commands and thresholds remain in force. This document describes the
setup contract; successful hosted extraction, query and upload processing must be established by
the [CodeQL workflow](https://github.com/JasonStys/engineering-documentation-foundry/actions/workflows/codeql.yml)
at its exact event revision. A green application test suite cannot substitute for that analysis.
Review both categories and open alerts in **Security → Code scanning**, including the analyzed
revision and extraction warnings. A completed job alone is not a zero-alert assertion.

## Limitations and review

PDF bytes, native parser internals, Jinja template coverage and migrated technical meaning are not established by this scan. Defensive parsing, escaping, resource bounds, publication gates and human review remain required. Static analysis can miss vulnerabilities and is separate from dependency auditing.
This CI/documentation change introduces no app release, package format or account-data migration.
